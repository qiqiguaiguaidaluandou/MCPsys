## 1. 修复：新建用户失败时只显示「请求失败 (422)」而看不到原因

**症状**：Web 用户管理页点「新建用户」，密码填短（如 `test1`，5 字符）提交后控制台报
`POST /api/v1/users 422`，UI 只弹一条「请求失败 (422)」，看不到「密码至少 8 位」这种字段级原因。

**根因**：两条独立缺陷叠加。

1. 前端 form 校验缺失：`UserListPage.vue` 只做了非空检查，未与后端
   `UserCreate`（`username` 3–64、`password` 8–128、`role` 必填）的约束对齐 →
   非法输入直接打到后端走一圈才被拒。
2. 全局 axios interceptor 错误格式化：`client.ts` 把响应类型声明成
   `AxiosError<{ detail?: string }>`，对 FastAPI 422 的 `detail: []`
   数组形态判 `typeof === 'string'` 一律落空，最终只能展示「请求失败 (422)」。

**改法**：

- 改 `services/web/src/api/types.ts`：新增 `ApiErrorItem`（覆盖 `type/loc/msg/ctx/input`），
  `ApiError.detail` 改成 `string | ApiErrorItem[]`，与 FastAPI 422 实际结构对齐。
- 改 `services/web/src/api/client.ts`：
  - 提取并导出 `formatDetail(detail)`：
    - `string` → 原样返回
    - 数组 → 每条按 `loc 去掉 'body' 前缀后 join('.') + ': ' + msg` 格式化，多条用 `；` 拼接
    - 其他 → 空串
  - interceptor 改用 `formatDetail` 取代旧的 `typeof === 'string'` 判断。
- 改 `services/web/src/views/users/UserListPage.vue`：
  - 引入 `FormInstance` / `FormRules`，新增 `formRef`。
  - 新增 `rules`：`username` 3–64、`password` 8–128、`role` 必填，与后端 Pydantic 约束 1:1。
  - 模板 `<el-form>` 绑 `ref / :model / :rules`，每个 `<el-form-item>` 改用 `prop=`，
    去掉旧的 `required` 静态属性。
  - `onCreate` 改为先 `formRef.value.validate()` 失败即 return，成功后调 `createUser`，
    提交完成再 `formRef.value.resetFields()`。
- 加 `services/web/tests/unit/client.test.ts`：新增 `describe('formatDetail')` 5 例
  （string / undefined / 单条带 body loc / 多条 join；/ loc 缺失或为空回退到 bare msg）。

**验证**：

- `npm run typecheck` 通过
- `npm run lint` 0 errors（仍有 10 条与本次无关的预存 warning）
- `npm test` 22/22（其中 client.test.ts 由 3 例 → 8 例）

**未覆盖**（待后续判断是否成单独条目）：

- `ApplicationListPage.vue` / `ServiceCreatePage.vue` 等其他 form 同样只做了非空校验，
  没和后端约束对齐。此次只修了用户管理表单；其他表单的 422 反馈现在虽然能正确显示字段错误
  （interceptor 通道已修），但仍然存在「前端没拦在客户端、要走后端往返」的体验问题。
