## 1. 服务管理：「注册新服务」按钮无效

**症状/需求**：`/services` 页面右上角「注册新服务」按钮 admin/operator 可见，点击后浏览器 URL 变成 `/services?new=1`，但页面无任何反馈——既不弹对话框，也不跳转。后端 `POST /api/v1/services` 与前端 `createService()` 均已就绪，**只差一个表单入口**。

**根因/范围**：

- `services/web/src/views/services/ServiceListPage.vue:54` 的按钮 `@click="router.push('/services?new=1')"`，全工程没有任何地方监听 `new=1` 这个 query，也不存在「服务创建对话框」组件 → 纯占位代码。
- 同目录 `ApplicationListPage.vue` 已有 `el-dialog` + 表单 + `createApplication()` 的完整实现，作为参照模板复用。
- 字段以前端 `CreateServicePayload` 类型为准：`slug` / `display_name` / `endpoint_url` / `description` / `owner_team` / `rate_limit_qps`。**不**包含 `tags`——前端 payload 类型本来就没有暴露，后端虽支持但本次不顺手加，避免 scope 漂；后续若有需求单独条目处理。
- `transport` 字段后端枚举只有 `streamable_http`，沿用默认值，不在表单暴露。
- slug 客户端做正则校验（与后端 `SLUG_RE` `^[a-z0-9][a-z0-9-]{0,62}[a-z0-9]$` 一致），避免非法输入往返。其余字段交后端 422 反馈（client.ts interceptor 已能正确格式化字段级错误，见 2026-05-11 小需求批次 #1）。

**改法**：

- 改 `services/web/src/views/services/ServiceListPage.vue`：
  - import 增加 `reactive`、`createService`、`ElMessage`。
  - 新增 `SLUG_RE` 常量与后端正则一致。
  - 新增 `newDialog` reactive（`visible` / `submitting` / `form` 六字段）与 `resetForm()` / `onCreate()`。
  - 按钮 `@click` 由 `router.push('/services?new=1')` 改为 `newDialog.visible = true`，删除无意义的 query 跳转。
  - 模板末尾追加 `<el-dialog v-model="newDialog.visible" title="注册新服务" width="520">`，六个 `<el-form-item>` 与 ApplicationListPage 风格一致；限流 QPS 用 `el-input-number`，留空表示不限。

**测试**：

不新增单元测试（UI 流为 element-plus 弹窗 + axios，单测 ROI 低；与 `2026-05-11 小需求批次 #2/#3` 同样判断）。客户端 slug 校验、后端 422 格式化通道已有覆盖。

**验证**（2026-05-12 执行结果）：

- `pnpm typecheck` → clean
- 手工验证（待用户在浏览器端跑一遍）：
  ① admin 登录 → 服务目录 → 点「注册新服务」→ 弹对话框
  ② 三必填留空 → 客户端阻断提示
  ③ slug 写非法字符（如大写 / 下划线）→ 客户端阻断提示
  ④ 合法输入提交 → 弹「服务注册成功」→ 列表多一行
  ⑤ 重复 slug → 后端 409 → toast 显示「slug already exists」
  ⑥ viewer 登录 → 按钮不可见（`auth.hasRole('admin', 'operator')` 把关）

**未覆盖**：

- `tags` 字段未在表单暴露（前端 `CreateServicePayload` 本来就没暴露，本次保持类型边界，不顺手扩）。后续若需要，扩 `CreateServicePayload` + 表单 `el-input-tag` / 多选即可。
- 其它列表页（API Key 列表 / Permission 列表 / User 列表等）尚未逐一盘点是否存在同款「按钮占位但无对话框」情况。User 已在 2026-05-11 批次 #2/#3 处理过；Application 已具备完整对话框；本批次仅修 Service。其它列表页留作后续条目。
- 服务注册后**未自动跳详情页**——保持与 Application 一致，提交后停留在列表。是否要跳详情让用户立刻配权限，是 UX 范畴的小议题，后续再判断。
