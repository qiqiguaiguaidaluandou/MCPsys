# 移除"服务版本管理"死功能

时间窗：2026-05-20。延续 `2026-05-19-服务健康检查实现.md` / `2026-05-20-调用日志body保留.md` 反复点出的「schema/UI 占位都在、就是没 writer」反模式。这次是反向决策：服务版本管理这个 v1 规划功能**确认不做**，于是把它从 v1 起就埋下、却从未实现的死脚手架按 `api_keys.last_used_at` 同样口径整体清掉（schema + 模型 + 迁移 + 后端 + TS + 测试 + UI）。

条目结构沿用：症状/需求 → 根因/范围 → 改法 → 测试 → 验证 → 未覆盖。

---

## 1. 整体移除 mcp_service_versions 表 / call_logs.service_version 列 / 前端版本占位

**症状/需求**：

- 服务详情页有一个禁用的「版本（v1）」tab、左侧导航「v1 即将上线」组里有一个禁用的「服务版本」项——都是点不动的占位。
- 用户确认：**不需要服务版本管理这个功能**。于是不只是摘掉灰 tab，而是把整套死脚手架清干净，避免又留一堆 last_used_at 式的死字段/死表。

**根因/范围**：

- spec `docs/specs/2026-04-30-mcp-management-system-design.md` 把「服务版本管理 `mcp_service_versions`」列在**后续（非 MVP）功能**（§348），并规划了 `POST /api/v1/services/{id}/versions`（§314）、manifest 记录 tools 列表（§156-157）。但全程未实现：
  - `McpServiceVersion` 表/模型建了（含 `is_current` / `manifest` / `endpoint_url`），全仓库 **0 个读写点**。
  - `call_logs.service_version` 列建了，gateway 三处写入全部写死 `None`（`mcp.py`），永远 NULL。
  - 前端 tab / 导航项 `disabled`，无任何接口（`api/services.ts` 无 version 函数）。
- 决策：**整体删除**，不保留。空表 + 全 NULL 列 ⇒ 删除不丢任何真实数据。
- 不动 spec 文档（spec 是设计史料，保留「曾规划过」的记录；本次只清代码）。
- 0001 历史迁移**不改**（它是已落库的事实）；新增 0008 做正向 drop、downgrade 完整重建。

**改法**：

`packages/mcpsys_shared/src/mcpsys_shared/models.py`：

- 删除 `McpServiceVersion` 整个类。
- 删除 `CallLog.service_version` 列。
- 删除随之失效的 `Boolean` import（只被 `is_current` 用过）；`UniqueConstraint` 仍被 `ServicePermission` 用，保留。

`services/control_plane/alembic/versions/0008_drop_service_versions.py`（新建）：

- upgrade：`op.drop_column("call_logs", "service_version")` + `op.drop_table("mcp_service_versions")`。
- downgrade：完整重建 `mcp_service_versions`（镜像 0001 的列/约束）+ 重新 `add_column` 回 `call_logs.service_version`。

`services/gateway/src/gateway/telemetry.py`：删 `CallLogEntry.service_version` 字段。
`services/gateway/src/gateway/routers/mcp.py`：删三处 `service_version=None,`（denied / success / throttled 三条日志路径）。
`services/control_plane/src/control_plane/routers/call_logs.py`：删 `CallLogDetail.service_version` 字段。

`services/web/src/api/call-logs.ts`：删 `CallLog` 接口里的 `service_version`。
`services/web/src/views/call-logs/CallLogDetailPage.vue`：删「服务版本」描述项。
`services/web/src/views/services/ServiceDetailPage.vue`：删禁用的「版本（v1）」tab。
`services/web/src/components/nav/SideBar.vue`：删「v1 即将上线」组里的 `versions` 项（`permissions` / `config` 两个占位保留）。
`services/web/src/i18n/locales/zh-CN.ts`：删随之失效的 `nav.versions` 文案。

测试同步：
- `services/gateway/tests/test_telemetry.py`：构造 `CallLogEntry` 处删 `service_version=None`。
- `services/control_plane/tests/test_call_logs.py`：构造行删 `service_version="1.0"`，详情断言删 `assert body["service_version"] == "1.0"`。

**测试**：

- 后端：gateway 41 passed、control-plane call_logs+retention 17 passed、services 19 passed、mcpsys-shared 2 passed。
- 前端：`pnpm typecheck`（vue-tsc --noEmit）干净；无残留 `service_version` 引用（仅 0001/0008 迁移文件保留）。
- 迁移链实跑（一次性 PG 容器）：`upgrade head` 后 `call_logs.service_version` 列数=0、`mcp_service_versions` 表数=0；`downgrade -1` 后列数=1；再 `upgrade head` 干净。up/down/up 三段验证通过。

**验证**（待用户在测试环境跑）：

1. `alembic upgrade head` → `\d call_logs` 无 `service_version` 列、`\dt` 无 `mcp_service_versions` 表。
2. 服务详情页无「版本」tab；左侧导航「v1 即将上线」组只剩「权限管理」「配置中心」。
3. 调用日志详情页无「服务版本」行，其余字段正常。
4. 既有调用日志/网关代理不受影响（service_version 本就全 NULL）。

**未覆盖**：

- **spec 文档未改**：spec 仍记载 `mcp_service_versions` 的设计与规划接口。保留作为「曾经的设计意图」史料；若将来要彻底从文档抹掉再单独处理。
- **重新启用成本**：若未来又想做版本管理，需要重建表/列（downgrade 已提供模板）并补 `POST /services/{slug}/versions` + gateway 按 `is_current` 解析 + 前端接入——等于从头实现，本次删除不为它预留任何东西。
